B TIER · PARALELISMO

🌊 Dynamic Workflows

Dynamic Workflows é quando o Claude escreve um script que roda — em casos extremos — até 1.000 agentes para dar conta de trabalhos enormes. Em vez de processar tudo numa fila, ele espalha o trabalho em paralelo e junta no fim. É a base que aparece de novo em outras features deste módulo (deep research, ultrareview).

🧩 Como ele divide o trabalho

O segredo não é "um agente gigante", e sim muitos agentes pequenos coordenados por um script que o próprio Claude escreve na hora.

  • •Trabalhos divisíveis (varrer milhares de arquivos, processar lotes) caem como uma luva.
  • •Processa em paralelo muito bem — o tempo total despenca.
  • •É novo: ainda está achando o lugar certo no dia a dia.

💡 Dica prática

Como usa muitos tokens, reserve dynamic workflows para tarefas realmente grandes e divisíveis. Para algo pequeno, um único agente ou alguns subagents já bastam.

Token-intensive

Use em tarefas grandes.

B TIER · ISOLAMENTO

🌿 Git Worktrees

Quando vários agentes trabalham no mesmo repositório ao mesmo tempo, o risco é óbvio: colisão. Git Worktrees resolve isso rodando cada agente numa cópia isolada do repo, para que eles nunca pisem um no trabalho do outro, e mergeia tudo no fim. É o complemento natural dos dynamic workflows.

Exemplo cópias isoladas · merge no fim 
main
├─ worktree/feature-a   agente 1  (isolado)
├─ worktree/feature-b   agente 2  (isolado)
└─ worktree/fix-c       agente 3  (isolado)

# cada um trabalha sem colidir → merge de volta na main

✓ Quando vale muito

  • ✓Trabalhando em time no mesmo repo.
  • ✓Várias features tocadas ao mesmo tempo.
  • ✓Agentes paralelos que não podem se atrapalhar.

✗ O que evitar

  • ✗Vários agentes editando a MESMA branch ao vivo.
  • ✗Esperar paralelismo sem isolar — vira conflito.
  • ✗Esquecer de mergear no fim e perder o trabalho.
Cópia isolada

Um worktree por agente.

Sem colisão

Ninguém pisa no outro.

Merge no fim

Tudo volta junto.

Time

Várias features de uma vez.

B TIER · REVIEW NA NUVEM

🛡️ Ultrareview

Ultrareview é um slash command que sobe uma frota de agentes na nuvem (no estilo code review) para revisar o seu código. O diferencial: cada agente verifica cada bug antes de reportar, o que reduz o ruído de falsos positivos que assola revisões automáticas comuns.

1

Você dispara o comando

Roda o slash command sobre o diff/projeto; o trabalho vai para a nuvem em vez de travar o terminal.

2

A frota verifica em paralelo

Vários agentes analisam ao mesmo tempo e cada bug suspeito é checado antes de virar relatório.

3

Você recebe o que importa

Em vez de uma lista cheia de ruído, chegam achados já verificados — mais sinal, menos falso positivo.

💡 Dica prática

Por rodar na nuvem, você dispara o ultrareview e continua trabalhando no terminal. Pense nele para o review pesado antes de um merge importante.

Slash command

Um comando dispara tudo.

Frota na nuvem

Não trava o terminal.

Verifica antes

Cada bug é checado.

Menos ruído

Mais sinal por achado.

B TIER · PESQUISA

🔬 /deep-research & Advanced Research

Você pede uma pesquisa e ele invoca automaticamente um dynamic workflow, espalha buscas na web (e nos seus apps conectados) e devolve UM relatório citado. É o paralelismo do tópico 1 aplicado a pesquisa: dezenas de buscas ao mesmo tempo, sintetizadas numa resposta com fontes.

📚 O que acontece por baixo

Em vez de uma busca de cada vez, ele orquestra muitas em paralelo e só então redige — com referências.

  • •Invoca um dynamic workflow sem você precisar pedir explicitamente.
  • •Busca na web e também nos seus apps/conectores.
  • •Entrega um único relatório citado, não 30 abas para você ler.

💡 Dica prática

Trate como uma pesquisa de verdade: peça escopo, perguntas-guia e fontes preferidas. Quanto mais clara a pergunta, melhor o relatório citado de volta.

B TIER · AÇÃO NA TELA

🖱️ Claude in Chrome & Computer Use

Claude in Chrome é um painel lateral que clica, preenche formulários e age entre as abas do navegador. Já o Computer Use é o aponta-e-clica genérico: usa qualquer app na tela quando não existe um conector. Juntos, estendem o alcance do Claude para o que vive fora do terminal.

✓ Claude in Chrome

  • ✓Clica e navega entre abas como você faria.
  • ✓Preenche formulários no painel lateral.
  • ✓Ótimo quando o fluxo vive todo no navegador.

✓ Computer Use

  • ✓Aponta-e-clica em qualquer aplicativo.
  • ✓Plano B universal quando não há conector.
  • ✓Usa a tela como um humano usaria.

💡 Dica prática

Prefira conector quando existir (mais rápido e confiável); use o aponta-e-clica como recurso final, para apps que não têm integração.

Entre abas

Clica e preenche.

B TIER · A COLA DO DIA

🧱 O ecossistema B

Vários recursos do Tier B não brilham sozinhos, mas amarram o seu dia a dia: reaproveitam contexto, ajudam a retomar onde você parou e dão superfícies novas para o Claude agir. Vale conhecer todos de relance.

O kit completo ecossistema · Tier B 
Projects     workspaces: chats + arquivos + instruções juntos
Memory       carrega contexto de chats antigos
/recap       mostra o que a sessão fazia quando você volta
Artifacts    renderiza num painel editável (+ Interactive Charts)
# e ainda: Browser Recording · Claude for M365 · Mobile Push
#            Cross-Device Convo · Connectors Directory

✓ Para que servem

  • ✓Projects: tudo de um trabalho num só workspace.
  • ✓Memory + /recap: retoma contexto sem reexplicar.
  • ✓Artifacts & Charts: painel editável e gráficos no chat.

✗ Mal-entendidos comuns

  • ✗Achar que /recap "lembra de tudo" — ele resume o estado da sessão.
  • ✗Confundir Memory com salvar arquivos manualmente.
  • ✗Ignorar o Connectors Directory e reinventar integrações.

💡 Dica prática

O /recap é especialmente ótimo com muitas abas abertas: ao voltar a uma sessão, ele te mostra o que estava em andamento antes de você continuar.
