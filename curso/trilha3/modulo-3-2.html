#6 · S TIER

🤖 Subagents

Subagents são agentes em segundo plano que rodam em paralelo — cada um no seu próprio context window. Podem ser invocados automaticamente ou a pedido. A diferença para os Agent Teams: subagents não conversam entre si; eles só reportam ao terminal principal que os criou. É a forma mais limpa de fazer várias coisas ao mesmo tempo sem poluir o seu contexto.

🧩 Subagents como arquivos

No seu .claude você não tem só skills, rules e workflows — também tem agents. São arquivos markdown que definem o que aquele agente faz, quais ferramentas pode usar e quais skills vivem dentro dele. Invocados quase como uma skill.

  • •Cada subagent tem contexto isolado — não enche a sua janela principal.
  • •Rodam em paralelo: ótimos para pesquisar, varrer arquivos, ou tarefas independentes.
  • •Reportam só ao terminal que os criou — sem conversa cruzada.

#5 · S TIER

🔁 /loop

O /loop faz um prompt se repetir num intervalo até uma condição. Por baixo, ele usa a ferramenta de criação de cron — então os loops ficam presos à sessão: cada terminal tem os seus, e fechar o terminal mata o loop. Eles também se auto-desligam depois de ~7 dias de terminal aberto.

Exemplo cron · vinculado à sessão 
/loop a cada 1 minuto, me lembre de beber água

# ou em linguagem natural, sem o slash:
configure um loop recorrente para checar a fila a cada 20 minutos

💡 Dica prática

Você não precisa do /loop para invocar — basta pedir em linguagem natural ("rode isto a cada hora"). Use loops curtos para lembretes e checagens leves; para algo que precisa rodar com a máquina fechada, o lugar certo é Routines (#3), não o loop.

Intervalo

Repete a cada X tempo.

Cron local

Usa a ferramenta de cron.

Preso à sessão

Fechou, morreu.

Auto-stop

~7 dias de terminal.

#4 · S TIER

📱 Remote Control

Remote Control deixa você dirigir a sua sessão local do Claude Code pelo celular ou pela web. Habilitou, ganhou um link; abriu no telefone (ou no app Claude → Code), e está controlando a mesma sessão — sincronizada em tempo real. O que você digita no celular aparece no computador, e vice-versa.

1

Habilite na sessão

Peça "enable remote control" na sessão que você quer levar com você. Ele gera um link único.

2

Abra no celular

Use o link ou o app Claude (aba Code). A mesma sessão aparece na palma da mão.

3

Continue de qualquer lugar

Saia para uma caminhada e mantenha a sessão viva — brainstormando ou construindo. Cada mensagem ecoa nos dois dispositivos.

Mesma sessão

Não é uma cópia.

Tempo real

Sincroniza nos dois lados.

Link ou app Claude.

#3 · S TIER

⏰ Routines

Routines é a capacidade de agendar um agente de verdade — não um script Python determinístico. Você agenda o seu terminal Claude Code exatamente como conversaria com ele. Pode ser local ou na nuvem (rodando com o laptop fechado). Crie com /schedule; gerencie pelo desktop app, com visão de calendário e lista.

✓ Bom uso de Routine

  • ✓Resumo diário do que mudou nos seus projetos.
  • ✓Varredura semanal de uma fonte e relatório.
  • ✓Rotina na nuvem que roda de madrugada, laptop fechado.

✗ Não confundir

  • ✗Não é o /loop (esse vive só na sessão aberta).
  • ✗Não é "só uma chamada de API" — é um agente completo.
  • ✗Não precisa do terminal aberto se for cloud.

💡 Dica prática

O ganho real de Routines é ter um agente na agenda, não um robô burro. Ele pode pesquisar, decidir e escrever — então capriche no prompt da rotina como capricharia numa instrução normal.

Agente real

Local ou cloud

#2 · S TIER

📊 Status Line

Provavelmente o recurso mais subestimado de todos. A status line é uma barra inferior scriptável: mostra o modelo, o nível de effort e — o mais importante — quanto do context window já foi consumido. É a correção mais fácil que existe: /statusline e descreva o que quer (pode até mandar um screenshot).

Recriação ilustrativa (não é screenshot real)
Opus 4.8 · effort: high · ctx 27% 274k / 1M tokens

✓ Por que importa tanto

  • ✓Você vê na hora quando precisa fazer handoff, /clear ou /compact.
  • ✓Sabe o modelo e o effort sem adivinhar.
  • ✓Foi o motivo de muita gente migrar da extensão para o terminal.

✗ Trabalhar sem ela

  • ✗Estourar o contexto sem perceber e perder qualidade.
  • ✗Não saber se está no modelo/effort certo para a tarefa.
  • ✗Descobrir tarde demais que devia ter compactado.

💡 Dica prática

Combine a status line com /context (o que está enchendo a janela) e /usage (tokens e custo). Juntos, eles te dão controle total sobre o recurso mais escasso da sessão: o contexto.

👑 #1 · O RECURSO Nº 1

⚡ Skills

O recurso número um — o que dá mais alavancagem no dia a dia. Uma skill é, na essência, uma receita: assim como você abre o livro de receitas para fazer uma lasanha em vez de improvisar de memória, o agente abre a skill e segue os passos. Resultado: ele faz a tarefa de forma muito mais consistente do que se você repetisse o mesmo prompt toda vez.

📖 A receita do agente

Skills são arquivos markdown que vivem no seu .claude. Por isso são tão poderosas:

  • •Você cria as suas e puxa as de outras pessoas (plugins trazem skills, hooks e MCP juntos).
  • •São versáteis: podem ter muitos passos e ferramentas, ou ser um único prompt de 4 frases.
  • •Encadeiam: uma skill pode rotear para outra.
  • •Funcionam no Claude Code, no Chat e no Cowork — e dá para compartilhar com o time.

✓ Quando virar skill

  • ✓Um prompt que você se pega repetindo (ex.: handoff de sessão).
  • ✓Um processo com passos fixos (thumbnails, apresentações, cortes de vídeo).
  • ✓Algo que precisa sair igual toda vez — consistência > improviso.

✗ Armadilhas

  • ✗Achar que skill precisa ser complexa — pode ser 4 frases.
  • ✗Re-explicar o mesmo processo por prompt toda sessão.
  • ✗Não revisar/refinar as skills com o tempo (elas evoluem).

💡 Dica prática

Comece pela skill mais boba que você tem: aquele prompt de quatro frases que você digita toda hora. Transforme em /comando. É o caminho mais rápido para sentir por que Skills é o nº 1.

Receita

Passos prontos para seguir.

Consistência

Igual toda vez.

Compartilhável

Markdown, com o time.

Onipresente

Code, Chat e Cowork.
